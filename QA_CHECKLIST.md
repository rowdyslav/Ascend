# ASCEND — Чек-лист ручного QA (iOS PWA)

Дата сборки: см. `git log -1`. Целевое устройство: iPhone (Safari, standalone PWA).
Ожидаемые адреса: фронтенд http://localhost:8550 · API/Swagger http://localhost:8000/docs · Mongo :27017.

## 1. Запуск

```bash
docker compose up -d --build
```

- Проверка, что всё поднялось: `docker compose ps` → `ascend-api-1`, `ascend-frontend-1`, `ascend-mongo-1` — все `running`.
- Логи при проблемах: `docker compose logs -f api` и `docker compose logs -f frontend`.
- Полный сброс данных (пересид): `docker compose down -v && docker compose up -d --build`.

## 2. Установка PWA на iPhone

1. В Safari на iPhone открой `http://<IP-компьютера>:8550` (телефон и ПК в одной сети; если фронт поднят локально на другом хосте — использовать его адрес).
2. Тап **Share (Поделиться)** → **Add to Home Screen / «На экран “Домой”»**.
3. Имя приложения должно быть **ASCEND** (подтянется из `apple-mobile-web-app-title`) → **Добавить**.
4. Запустить с домашнего экрана: приложение должно открыться в полноэкранном (standalone) режиме без адресной строки Safari, с тёмной темой.

## 3. Как имитировать медленное соединение (для проверки лоадеров)

- **Desktop (рекомендуется):** Chrome/Edge DevTools → Network → **Slow 3G** → открыть http://localhost:8550 и ходить по табам.
- **iPhone:** отдельного «троттлинга» в iOS нет — либо реальная медленная сеть, либо тест лоадера через DevTools. Для проверки *ошибки* API: `docker compose stop api` → на экранах должен показаться текст ошибки, лоадер обязан исчезнуть → `docker compose start api`.

## 4. Чек-лист (15 пунктов)

### Общее

- [ ] **1. Загрузка и тема.** Приложение стартует в тёмной теме (`ThemeMode.DARK`) без «белой вспышки»; заставка с логотипом сменяется экраном «Сегодня».
- [ ] **2. Safe Area.** В standalone-PWA: контент не залезает под Dynamic Island/вырез (сверху) и под Home Indicator (снизу); таб-бар приподнят над нижним жестом «домой», все 5 вкладок нажимаются без промахов; проверить и в ландшафтной ориентации.
- [ ] **3. Opacity-фидбек кнопок.** `PrimaryButton`/`SecondaryButton`/круглые иконки-кнопки при нажатии плавно затемняются (opacity ≈ 0.7) и возвращаются (~120 мс, анимация 200 мс); на десктопе при наведении — лёгкий дим; быстрые повторные тапы не оставляют кнопку «залипшей» полупрозрачной; ripple при этом не ломается.
- [ ] **4. Лоадеры.** При переходе на «Тренировки» и «Аналитику» на Slow 3G появляется полупрозрачный оверлей «Загрузка данных...» со спиннером; после получения данных он исчезает; при остановленном API (`docker compose stop api`) показывается текст ошибки, оверлей не «висит» навсегда.

### Экран «Сегодня»

- [ ] **5. Прогресс дня.** Кольцо (teal→purple градиент) показывает % выполнения; тап по метрике (вес/сон/энергия/…) открывает нижний лист со слайдером, сохранение обновляет карточку и кольцо.
- [ ] **6. Закрытие дня.** «Закрыть день» → диалог со списком незавершённого → подтверждение закрывает день (карточка «День закрыт ✓», календарь в Аналитике показывает зелёный день); повторное закрытие блокируется сообщением «День уже закрыт».
- [ ] **7. Карточка тренировки.** «Начать» / «Заполнить позже» ведут на экран «Тренировки»; «День отдыха» отмечает день и пересчитывает прогресс.

### Экран «Тренировки»

- [ ] **8. Планировщик недели.** Переключение дней, создание Push/Pull/Legs/«День отдыха», «Копировать прошлую неделю» — план обновляется без ручной перезагрузки; при каждой перерисовке мелькает лоадер.
- [ ] **9. Активная сессия.** Добавление сета (упражнение, вес×повторы, RIR, отдых) — сет появляется карточкой с 1RM и тонажем; сообщение «🏆 Новый рекорд!» при PR; «Копировать прошлый» и «Дроп-сет» заполняют форму корректно.
- [ ] **10. Таймер отдыха — основной сценарий.** После сохранения сета стартует отсчёт: градиентное кольцо заполняется, текст «Отдых: N сек» → «Отдых завершён» → кольцо сбрасывается.
- [ ] **11. Таймер отдыха — сворачивание/разворачивание.** Запустить таймер → заблокировать iPhone (Sleep) на 30–60 с → разблокировать: таймер продолжает тикать и корректно завершается, без ошибок и «зависшего» кольца (время не обязано совпадать с wall-clock — это ожидаемо). Повторить с уходом в другой таб и возвратом: отсчёт не сбрасывается.
- [ ] **12. Завершение тренировки.** «Завершить тренировку» открывает нижний лист: длительность, сложность, памп, энергия, чекбокс боли, комментарий → «Сохранить»; карточка получает статус «Готово», данные видны в Аналитике.

### Экран «Питание»

- [ ] **13. Продукты, порции, рецепты, копирование.** Поиск продукта → нижний лист «Вес, г» → пересчёт нутриентов и добавление в приём пищи; прогресс-бары дня обновляются; удаление записи работает; сохранение/применение рецепта и «Копировать приёмы» с другой даты — без дублей и потерь.

### Экран «Протокол» и «Аналитика»

- [ ] **14. Логирование доз.** Быстрая отметка «✓» логирует приём; повторная отметка того же пункта в течение 5 минут показывает диалог «Уже отмечено в HH:MM. Повторить?»; инъекция с зоной/стороной/реакцией сохраняется, остаток на складе уменьшается, «Протокол» в Аналитике пересчитывает % выполнения.
- [ ] **15. Аналитика.** Подтабы (chips) переключаются с активным состоянием; календарь открывает детали дня нижним листом; графики веса/тоннажа/макро отрисовываются (matplotlib); «Анализы» — создание теста и маркеров с флагами выхода из нормы.

## 5. Критерии прохождения

- Все 15 пунктов отмечены без «жёстких» багов (краши, потеря данных, залипшие лоадеры, нерабочие кнопки).
- Допустимо задокументировать как **известные ограничения** (в поле «Комментарий»): неточность таймера при блокировке экрана, ripple поверх opacity на Material-кнопках.
